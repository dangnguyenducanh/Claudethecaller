# Process for T3.2: library MCP tools, `/api` capability routes, overrides, restore, blob cleanup (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through `deps` (`repos`, `cache`, `submit`, `ctxOf`) and temp directories as `claude_home`. The limits in `libraryApiLimits` are fixed when the schemas are built, so limit tests use the default value (equal is valid, one more is `invalid`) and one test pins every default. Modules: `apps/web/src/library/`, `packages/shared/src/schemas/library/`, `apps/worker/src/library/blobs.ts`, plus the small additions to `packages/core/src/library/index.ts`, `apps/worker/src/library/handlers.ts`, `apps/worker/src/library/index.ts` and `packages/shared/src/repositories/{library,tenancy.cases,system}.ts` that DECISIONS.md D11, D20 and D21 name.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are `repos.library.*`, `repos.projects.get`, `repos.system.cleanup.deleteUnreferencedBlobs` in `packages/shared/src/repositories/`; `resolveServed`, `diffManifests`, `parseFrontmatter`, `isName`, `isLabel` in `packages/core/src/library/`; the `library.changed` handler and its private `bodyOf` in `apps/worker/src/library/handlers.ts`; `submitJob` and `payloads.ts` in `packages/shared/src/queues/`; `keys.ovr`, `ttl.ovr`, `publishInval` and the `ovr.changed` event in `packages/shared/src/cache/`; `Handler` and `runAttempt` in `apps/worker/src/jobs/`; the route-object shape `nudgeRoute` uses (a Fastify-style `(req, reply)` handler). The real upstream producer is the T3.1 scanner: build a small Claude Code home in a temp dir (a skill with `SKILL.md` + `ref.md` + an executable `scripts/run.sh`, an agent), run `scanLibrary` from `@ctc/worker`'s library module on it against a scratch schema in a throwaway script, and keep the resulting `get_capability` reply as `apps/web/src/library/fixtures/get-capability.json` (no secrets, never copied from the real `~/.claude`).)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: equal is valid, one more is an error, pin the default. Compare error bodies and MCP results with `toEqual`. Must-NOT tests for every non-goal (no route outside the D9 list, no file deleted by restore, no label moved by restore or pin, nothing written in shared mode). Public names, temp dirs and scratch schema names only. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`repos.*`, `resolveServed`, `diffManifests`, `parseFrontmatter`, `isName`, `isLabel`, `keys.ovr`, `ttl.ovr`, `createSystemCtx`, `node:fs/promises`, `node:crypto`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
