D0  Purpose and callers. `llm.extract` learns durable facts (preference / convention / fact / skill_outcome) from what the user typed in a session and writes them through the write bands, so the next session starts with them (spec:468, spec:470 "always use pnpm"). `llm.summarize` turns one finished session into the 6 summary fields, so Monday's session starts with Friday's summary (spec:472). Callers: the worker main binds `memoryHandlers(deps)` into `startWorkers({handlers})` (apps/worker/src/jobs/index.ts:23-34, `handlers` keyed `'<queue>.<kind>'`); `runAttempt` validates the payload, runs the handler under the 120 s `llm` timeout and writes `jobs.result` / `jobs.error` (apps/worker/src/jobs/consumers.ts:50-107). Producers: the spool drain makes `llm.extract {userId, projectId?, sessionId, transcriptPath?}` on Stop and `llm.summarize {userId, projectId?, sessionId}` on SessionEnd after upserting the `sessions` row with `transcriptPath` (apps/web/src/spool/index.ts:152, :160); T4.3 `memory.distill` makes more `llm.extract` jobs. T4.3 reuses `applyBands` (`save_memory`, `memory.import`: "same bands", spec:524, spec:537), `sanitize`, `createEmbedder`, `createChat`. FROM-SPEC (spec:96 code map, spec:190, spec:513-523, spec:785) and FROM-CALLERS (packages/shared/src/queues/payloads.ts:21-22).

D1  Trust. Untrusted: (a) the job payload: it was built from a spool file anyone could write (T4.1 D1), so `transcriptPath` and `sessionId` are hostile until checked; `runAttempt` re-validates the shape, the handler checks the meaning; (b) every byte of the transcript (`.jsonl` lines that are not JSON, huge lines, rows of the wrong shape, prompt-injection text inside messages, secrets); (c) every byte of every model reply (llama-server's grammar can still give an empty list, wrong kinds, 10 KB strings, or invalid JSON when it hits `max_tokens`); (d) the embedder's reply (wrong length, NaN). Trusted: `deps` (the worker main builds them from the Zod-validated config). Failures this prevents: reading `/etc/shadow` or another user's files through `transcriptPath` and storing them as memories; a README or tool output quoted by the assistant becoming a "convention" that every later session sees as trusted context (only the user's own typed words feed `llm.extract`); a model reply crashing the worker or writing junk rows; secrets reaching the model. `userId` always comes from `payload.userId` (set by the drain from `deps.userId`, never from a file).       `maxTranscriptBytes` 32 MiB: a transcript file bigger than this is read from byte `size - maxTranscriptBytes` on, and the first (partial) line is dropped. Exactly 33554432 bytes is read whole.

D3  Output formats (exact).
    `llm.extract` result (what the handler resolves; `runAttempt` stores it in `jobs.result`): `{ facts: number, noop: number, update: number, supersede: number, add: number, skipped: number }` where `facts` = items in the reply, each kept fact increments exactly one of `noop|update|supersede|add`, and `skipped` counts items dropped by D4 or by `maxFacts` (so `facts = noop + update + supersede + add + skipped`). With no user words: `{ skipped: 'no_words' }` and no model call.
    `llm.summarize` result: `{ inserted: true }` or `{ inserted: false }` (same content or a summary of this session already stored); `{ skipped: 'exists' }` when the session already has a summary (no model call); `{ skipped: 'empty' }` when the session text is empty (no model call).
    Drops: the handler throws `new JobDropped(code)` from `@ctc/shared/queues`; `runAttempt` marks the row `dead` with `error = 'dropped:<code>'` and BullMQ does not retry. Codes: `bad_reply` (model reply invalid twice, D13/D14), `no_transcript` (no usable path, or the file does not exist / is not a regular file), `transcript_outside` (path fails D13 step 1), `runner_session` (D11), `no_session` (summarize: no `sessions` row of this user), `no_project` (summarize: the session row has no project; cannot happen with the T1.2 schema, kept as a guard). FROM-CALLERS (packages/shared/src/queues/submit.ts:43-50, apps/worker/src/jobs/consumers.ts:28-31, :100-103) and FROM-SPEC (spec:520 "`jobs.error = bad_reply`"); the codes and the `dropped:` prefix as stored: YOUR-CHOICE
    Memory row written by extract: `scope`, `kind`, `text` (sanitized, trimmed), `confidence` (D4), `source = { type: 'session', sessionId, transcriptPath }`, `embedding` (the fact's vector). No other field is set by this task. YOUR-CHOICE (the `source` shape).
    Summary row: the 6 fields (`request, investigated, learned, completed, nextSteps, notes`), `contentHash = summaryHash(sessionId, text)` where `text` is the exact summary input (D11) and `summaryHash(sessionId, text) = sha256 hex of 'summary-v1\n' + sessionId + '\n' + text`. D4  Bad input.
    Payload: shape errors never reach the handler (`runAttempt` marks them `dead payload_invalid`). Meaning errors are drops (D3 codes), never a throw of another class: a retry cannot fix them. FROM-CALLERS (apps/worker/src/jobs/consumers.ts:55-63).
    Extract reply: invalid (= retry once, D13) when it is not JSON, or not an object with an array `memories`. A valid reply with zero usable items is valid (result counts zeros). Per item (each bad item is `skipped`, the others are kept): not an object; `kind` not one of `KINDS`; `scope` not one of `SCOPES`; `text` not a string, empty after `sanitize` + trim, or longer than `maxMemoryChars`; `scope: 'project'` while the job has no `projectId`. `confidence`: a finite number is clamped to [0, 1]; missing or not a number → 0.5.
    Summary reply: invalid when it is not JSON, not an object, or none of the 6 keys holds a non-empty string after trim. Each field: a string → sanitized, trimmed, cut to `maxSummaryFieldChars`; anything else → `''`. Unknown keys ignored.
    Relation reply (D12): `'same'` or `'contradicts'` from `{relation}`; anything else → `null`.
    Transcript: a line that is not JSON, not an object, or not a D11 row is skipped; never an error.
    Embedder or chat failure (network error, timeout, HTTP status ≥ 400, malformed embed reply): `ModelError` is thrown out of the handler, so the attempt fails and BullMQ retries once (`llm` attempts 2), then the row is `dead` (spec:207 "`llm` jobs retried once then `jobs.error`"). This is a different "retry once" from the bad-reply retry inside one attempt. `RepoError`/`ConflictError` other than the cases D12 handles also propagate (attempt fails).
    FROM-SPEC (spec:520, spec:523, spec:560, spec:207); the per-item split, the clamp and the 0.5 default: YOUR-CHOICE

D10 `sanitize(text, o?)`, in this order: (1) remove each block from an opening tag to the first matching closing tag after it, both included, for exactly `<private>`, `<system-reminder>`, `<persisted-output>` (no attributes, case-sensitive; blocks may span lines; repeat until none is left); an opening tag with no closing tag removes everything to the end of the text; a lone closing tag is kept; (2) remove every line whose text, after leading whitespace, starts with `CTC_LINE_PREFIX` (`ctc: `), including its line break; (3) remove every char in U+0000-U+0008, U+000B, U+000C, U+000E-U+001F, U+007F (keep `\t`, `\n`, `\r`); (4) if `o.maxChars` is a positive integer, cut to that many UTF-16 code units, never splitting a surrogate pair (cut one shorter instead). It does not trim. Pure, never throws for a string; a non-string gives `''`. D11 Transcript → model input (a Claude Code `.jsonl`: one JSON object per line).
    User turn = a row with `type === 'user'`, `isMeta !== true`, `isSidechain !== true`, and `message.content` either a string or an array; an array that contains any part with `type === 'tool_result'` makes the row not a user turn. The turn text = the string, or the `text` of every part with `type === 'text'` and a string `text`, joined with `'\n'`. Then: remove Claude Code harness blocks `<command-name>…</command-name>`, `<command-message>…</command-message>`, `<local-command-stdout>…</local-command-stdout>`, `<local-command-stderr>…</local-command-stderr>`, `<local-command-caveat>…</local-command-caveat>` (same block rule as D10 step 1); replace `<command-args>X</command-args>` by `X`; `sanitize`; trim; drop it when empty or when it starts with `[Request interrupted`; cut to `maxTurnChars`. `userTurns` returns them in file order.
    `extractInput(turns)`: each turn as `User: <text>`, joined with `'\n\n'`, keeping the newest turns: whole turns are dropped from the oldest until the result is ≤ `maxUserChars`; if the newest turn alone is longer, the result is its last `maxUserChars` code units. No cursor is stored: every job reads the whole file and keeps the newest window (repeats meet themselves in the bands as NOOP). `''` when there are no turns.
    `sessionText(jsonl)`: in file order, the user turns as `User: <text>`, every assistant row (`type === 'assistant'`, not sidechain) as `Assistant: <text>` from its `type === 'text'` parts (sanitized, trimmed, cut to `maxTurnChars`, dropped when empty) and one `Tool: <name> <arg>` line per `type === 'tool_use'` part, where `<arg>` is `input.file_path`, else `input.command`, else `input.pattern`, else empty, sanitized and cut to 200 code units. Joined with `'\n'`. An assistant row's text parts are joined with `'\n'` into one `Assistant:` line, written before that row's `Tool:` lines. When longer than `sessionHeadChars + sessionTailChars`, the result is the first `sessionHeadChars` code units + `'\n[…]\n'` + the last `sessionTailChars`. Tool results never appear.
    `isRunnerSession(jsonl)`: `true` when any row has a string `cwd` containing `/.ctc/wt/` (an F4 workflow step's worktree, spec:121). Both handlers drop such a session (`runner_session`) before any model call.

D12 Bands. `bandOf(s, b)`: `s === null` (no live neighbour) or `s < b.update` → `'add'`; `b.update ≤ s < b.noop` → `'mid'`; `s ≥ b.noop` → `'noop'` (0.95 itself is NOOP, 0.85 itself is mid, 0.8499 is ADD). A non-finite `s` counts as `null`. `decide(s, r, b)`: noop → `NOOP`; add → `ADD`; mid → `UPDATE` when `r === 'same'`, `SUPERSEDE` when `r === 'contradicts'`, `ADD` when `r === null` (judge failed: keep both, hide nothing).
    `applyBands(ports, fact, b)`: (1) `embedding = embed(fact.text)`; (2) `n = nearest(fact.scope, embedding)` (the nearest live memory of the same user, scope and project; the repository's `nearest` with `limit: 1` and `similarity = 1 - cosine distance`); (3) only for the mid band: `r = judge(n.text, fact.text)`; (4) act: NOOP → `reinforce(n.id)`, result id `n.id`; UPDATE → `rewrite(n.id, fact.text, embedding)`; SUPERSEDE → `supersede(n.id, fact, embedding)`; ADD → `add(fact, embedding)`. Fallbacks: `rewrite` returning `null` (row gone) or throwing an error with `code === 'conflict'` (T1.3 `ConflictError`: that text already exists in the scope; matched by `code` so `@ctc/core` needs no import of the repositories) → `add(...)` (which reinforces the existing row on a hash conflict), action stays `UPDATE`; `supersede` returning `null` (old row no longer live) → `add(...)`, action stays `SUPERSEDE`. `judge` is called at most once per fact and never outside the mid band.
    Ports in the worker: `embed` = `deps.embed([text])[0]`; `nearest` = `repos.memory.nearest(ctx, {scope, embedding, limit: 1})`; `judge` = one `chat` call with `relationMessages` + `RELATION_SCHEMA`, temperature 0, parsed by `parseRelationReply`; a `ModelError` or invalid reply → `null` (no retry: the fallback is safe); `reinforce` = `repos.memory.reinforce(ctx, id, today())`; `rewrite` = `repos.memory.rewrite(ctx, id, {text, embedding, hash: memoryHash(text)})` (`memoryHash` from `@ctc/shared/memory-hash`); `supersede` = `repos.memory.supersede(ctx, oldId, input)`; `add` = `repos.memory.add(ctx, input)` with `input = {scope, kind, text, embedding, confidence, source}` (D3).
    FROM-SPEC (spec:479-486 the table, spec:521 "insert with ON CONFLICT … DO UPDATE reinforcement", spec:550) and FROM-CALLERS (packages/shared/src/repositories/memory.ts:50-61 `ON CONFLICT` reinforcement, :71-127 `nearest`/`reinforce`/`rewrite`/`supersede`, packages/shared/src/memory-hash/index.ts:12); the judge as a second model call, the null → ADD fallback and the rewrite/supersede fallbacks: YOUR-CHOICE (spec:484-485 say "same meaning" / "contradicts" without saying who decides)

D13 `llm.extract` flow, in order:
    1. Path. `p = payload.transcriptPath ?? (await repos.sessions.get(ctx, payload.sessionId))?.transcriptPath`, checked in this order: (i) not a non-empty string → drop `no_transcript`; (ii) not absolute, or not ending in `.jsonl` → drop `transcript_outside`; (iii) `realpath(p)` fails with ENOENT → drop `no_transcript`; (iv) `realpath(p)` not inside `realpath(<claude_home>/projects)` (with a leading `~` in `claude_home` expanded to `os.homedir()`), or `lstat(realpath(p))` not a regular file, or any other error → drop `transcript_outside`. Read with D2 `maxTranscriptBytes`, as UTF-8 (invalid bytes replaced).
    2. `isRunnerSession` → drop `runner_session`.
    3. `input = extractInput(userTurns(text))`; `''` → resolve `{skipped: 'no_words'}`.
    4. `raw = chat({messages: extractMessages(input), schema: EXTRACT_SCHEMA, temperature: 0}, signal)`; `parseExtractReply(raw, {hasProject})`. Invalid → once more with `extractMessages(input, {retry: <reason>})` and temperature 0.2 (a fresh request that tells the model why the first reply was rejected; the bad reply is not sent back); invalid again → drop `bad_reply`. A `ModelError` is not a bad reply (D4).
    5. For each kept fact, in reply order: `applyBands` with `ctx = {userId, projectId?}`; count its action.
    6. When at least one action happened and `payload.projectId` is set: `deps.cache?.epoch.rotate('mem', userId, projectId)`; a throw or `null` from it is logged (class name) and ignored. When nothing was written, no rotate.
    7. Resolve the D3 result.
    `signal` (the job's AbortSignal) is passed to every model call; when it aborts, the handler stops before the next write.
