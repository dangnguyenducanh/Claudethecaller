# Process for the T3.1 library scanner and `library` queue (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → assign to the exported `libraryLimits` object and restore it in `afterEach`. Modules: `packages/core/src/library/`, `apps/worker/src/library/`, plus the one D19 function in `packages/shared/src/repositories/library.ts`.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are `startWorkers`/`runAttempt` in `apps/worker/src/jobs/` (handler shape), `submitJob` and `payloads.ts` in `packages/shared/src/queues/` (`library.scan`, `library.changed`), `repos.library` and `repos.dedup` in `packages/shared/src/repositories/` (what the scanner writes), `publishInval` in `packages/shared/src/cache/`, `library.*`/`embed.*` in `packages/shared/src/env/schema.ts`. The real upstream producer is a Claude Code home layout: build one in a temp dir (a multi-file skill, an agent, a command, a YAML workflow, `plugins/installed_plugins.json`) with a small script, run `discoverRoots` + the walk on it once they exist, and keep the tree as `apps/worker/src/library/fixtures/` (text files only, no secrets, never copied from the real `~/.claude`).)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to `libraryLimits` (restore it after), equal is valid, one more is an error, pin the default. Compare skip codes and result shapes with `toEqual`. Must-NOT tests for every non-goal. Public names, temp dirs and scratch schema names only. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`repos.library.*`, `submitJob`'s input shape, `JobDropped`, the `yaml` package, `node:crypto`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
