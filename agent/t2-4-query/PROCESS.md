# Process for T2.4 graph query, explain, path, affected, neighbors, MCP tools and `/api/graph` (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → assign to the exported `queryLimits` or `graphApiLimits` object and restore it in `afterEach`. Modules: `packages/core/src/graph/query/`, `packages/shared/src/schemas/graph/`, `apps/web/src/graph/`.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the "call sites" are the spec sections named in DECISIONS.md D0 and the sibling surfaces `apps/web/src/library` and `apps/web/src/memory` whose plumbing you reuse. The real upstream producer is the T2.x pipeline: build the graph of a small temp project with `rebuildProject` into a scratch schema, dump `repos.graph.loadGraph` as `apps/web/src/graph/fixtures/mini-graph.json` and use it in the tests; read two or three real rows to see the exact `type`, `label`, `sourceLocation` and `meta.lines` shapes before you write `NodeRef`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to the limits object (restore it after), equal is valid, one more is an error or a cut, pin the default. Compare errors with `toEqual`/`toBe` on `code` and `message`. Must-NOT tests for every non-goal (no write except edge review, no file read outside the root, no DROPPED edge, no non-seed hub expansion). Public names only. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`sanitize`, `ApiError`, `parse`, the repositories). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass (the gate test `graph.query` last: it builds this repository's graph and takes several minutes).
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
