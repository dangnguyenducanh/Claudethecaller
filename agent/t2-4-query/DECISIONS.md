D3  Output formats. All JSON is plain (no `undefined`, no `Date`, no `userId`). `NodeRef = { id, label, type, kind, file: string | null, line: number | null }`; `file` = `sourceFile`; `line` = N of `sourceLocation` `L<N>`, else `null`.
    `where(n)` = `file:line` | `file` | `-`. Node text `T(n)` = `<label> [<type>] <where> (<id>)`.
    Confidence weights: `CONFIRMED 1`, `EXTRACTED 1`, `INFERRED 0.6`, `AMBIGUOUS 0.3`, `DROPPED 0`.
    Search JSON: `{ query: string, total: number, hits: Hit[] }`, `Hit = NodeRef & { score: number, hop: number, via: { from: string, relation: string } | null }`. Text: one line per hit `<tag> <score.toFixed(2)> <T(n)>`, tag `seed` (hop 0) or `hop<N>`;
      nothing found: `no matches`; truncated by budget or limit: last line `[truncated: <N> more]` where N = `total` − shown.
    Explain JSON: `{ node: NodeRef, excerpt: string | null, groups: { relation, direction: 'in' | 'out', total, edges: { node: NodeRef, confidence, score }[] }[] }`. Text: first line `T(node)`, then the excerpt lines (if any) each prefixed by 2 spaces, then per group a header
      `-<relation>->` (out) or `<-<relation>-` (in), then per edge `  <confidence> T(other)`, then `  … <N> more` when `total` > shown.
    Path JSON: `{ found: boolean, from: NodeRef, to: NodeRef, maxHops: number (the limit used), hops: { from: string, to: string, relation: string, confidence: string, forward: boolean }[], nodes: NodeRef[] }` (`nodes` = start, each hop's far end; empty when not found; `from === to` → `found: true`, `hops: []`, `nodes: [that node]`).
      Text: found → first line `T(start)` then per hop `  -<relation>-> T(next)` (forward) or `  <-<relation>- T(next)` (backward); not found → `no path within <maxHops> hops`.
    Affected JSON: `{ node: NodeRef, depth: number, total: number, truncated: number, groups: { type: string, nodes: (NodeRef & { depth: number, relation: string, via: string })[] }[] }`. Text: first line `a change to T(node) affects <total> nodes:` (always the word `nodes`), then per group a line `<type> (<count>)` and per node
      `  <depth> <relation> T(n)`; `total` 0 → the first line ends with `affects 0 nodes:` and nothing follows.
    Neighbors JSON: `{ node: NodeRef, total: number, neighbors: { direction: 'in' | 'out', relation, confidence, score, node: NodeRef }[] }`. Text: first line `T(node)`, then per neighbor `  <direction> <relation> <confidence> T(other)`; when there are none the whole text is exactly `no neighbors`.
    Stats JSON: `{ nodesByType: Record<string, number>, edgesByRelation: Record<string, number>, lastBuild: string | null, guardTrips: number }`. Build reply: `202 { job_id: string }`. Edge review reply: `200 { src, dst, relation, confidence, score, origin }`.
    Error body (routes) `{ error: { code, message, ...extra } }`, status by code as in spec:146-162 (`invalid` 422 with `path`, `not_found` 404 with `nearest` for a name, `ambiguous` 409 with `candidates`, `store_timeout` 504, `internal` 500 with the class name only); MCP error = `isError: true`, `text = JSON.stringify(body)`.

D10 Index. `buildIndex` keeps the nodes by id (first occurrence wins), keeps an edge only if both endpoints exist and `confidence` is not `DROPPED`; an unknown confidence string counts as `AMBIGUOUS`; a duplicate `(src, dst, relation)` keeps the highest weight (ties: the first); `score` defaults to 1.
    `degree(id)` = live in-edges + live out-edges (a self loop counts twice). `hubCut = max(hubMin, p99)` where `p99` = the degree at index `ceil(0.99 × n) − 1` of the ascending degree list (0 for an empty graph); `hubMin` default `queryLimits.hubMin`. Vectors are used only when `embedding.length` is the same for every vector and all values are finite (otherwise ignored).
    Edge lists are sorted by `(relation, other end id)` once, so every traversal is deterministic. FROM-SPEC (spec:266 DROPPED kept only for review, spec:308 hub rule); sorting, duplicate and unknown-confidence handling: YOUR-CHOICE.

D11 Name resolution `resolveName(index, name)`. `name` is trimmed; empty → `invalid`. `key(label)` = the label without one trailing `()` and one leading `.` (`.run()` → `run`, `search()` → `search`, `hybrid.py` → `hybrid.py`). Steps, the first that finds at least one node decides; exactly one → it; more → `ambiguous`; no step → `not_found`:
    1. exact id; 2. `key(label) === key(name)` (case-sensitive; `key(name)` strips the same decoration); 3. path form: `name` is `P::S` (split at the LAST `::`) → nodes whose `sourceFile` is `P` or ends with `/P` and `key(label) === S`; or `name` is a bare path → the nodes of type `file` or `page` whose `sourceFile` is `P` or ends with `/P`
       (a bare name with no `/` is not tried as a path); 4. case-insensitive `key(label)` equality; 5. `key(label)` starts with `key(name)` case-insensitively.
    `candidates` = the matches of the deciding step sorted by id, first 10, each `{ id, label (cleaned), hint }` with `hint` = `sourceFile::key(label)` or the id when there is no file. `nearest` (not_found) = the 5 distinct labels with the highest Dice coefficient over lowercase character bigrams against `key(name)` (> 0), ties by label then id; labels are cleaned.

D12 `searchGraph` (seed and walk). Steps: (1) `query` trimmed and cut to `queryMax` code points; empty → `invalid`. (2) Seeds, restricted to nodes whose `type` is in `types` when given:
    lexical: tokens = lowercase runs of letters/digits (`\p{L}\p{N}`+) of length ≥ `tokenMin`, distinct. For each label the distinct tokens of the label. `tier(t, label)` = max over label tokens `w`: 1000 if `w === t`, 100 if `w` starts with `t`, 1 if `w` contains `t`, else 0.
    `idf(t) = ln(1 + N / (1 + df(t)))`, `N` = node count, `df(t)` = nodes with a label token equal to `t` (computed once per index). `score(n) = (Σ over query tokens t with tier>0 of tier(t)·idf(t)) × (matched / queryTokens)²`. Keep the top `seeds` (3) with score > 0, ties by id; normalise by dividing by the best score (best = 1).
    dense: when `queryVector` is a finite vector of the index's vector length: cosine against every vector, keep nodes with cosine ≥ `floor` (0.3), top `denseSeeds` (10), score = cosine. A node in both channels keeps the larger score. Seeds are all of them, ordered by score desc then id.
    (3) Walk (`walkFrom`): BFS over live edges in BOTH directions to `depth` (2); a node reached for the first time at hop h gets `score = max over its hop-(h−1) parents p of score(p) × 0.5 × weight(edge)`; the edge weights of D3; `via` = the best parent and relation (ties: smaller parent id). A seed is always expanded; a non-seed node with `degree ≥ hubCut` is reported but not expanded.
    The type filter applies to the reported nodes only (the walk passes through other types). A seed keeps hop 0 and its seed score even when it is also reached by the walk.
    (4) Order: hop asc, score desc, id asc; cut to `limit` (default 10, max 50). `total` = hits before the cut. Seeds that fail the type filter never exist, so with `types` the hits are exactly the nodes of those types.
    Text (renderSearch) adds lines until `budgetTokens × charsPerToken` characters (newlines counted) would be exceeded; the footer is outside the budget. A hit line is never split; at least one hit line is always shown (judgment: an answer must not be empty only because one line is long).
    FROM-SPEC (spec:305-309 tiers 1000/100/1, IDF, coverage², at most 3 seeds, embedding top 10 ≥ 0.3, BFS depth 2, hub skip, seed × 0.5^hop × confidence; spec:325 text ≤ 2,000 tokens, seeds first then by hop, truncation footer; spec:206 TEI down → lexical only);
    the formulas for IDF and `coverage`, token rule, product of weights per path, seed expansion exception, tie rules, the text budget measure: YOUR-CHOICE (OPEN: coverage definition, hub exception).

D14 `findPath`. Names resolved by D11 (`from` first).
