# Process for T6.3: workflow engine, gates, fan-out and join, handoff, cleanup (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through `deps` (`repos`, `config`, `runsDir`, `reportBase`, `submit`, `loadWorkflow`, `now`, `log`) and assign to the exported `workflowLimits` / `engineLimits` / `startLimits` / `handoffLimits` objects, restoring them in `afterEach`. Modules: `packages/core/src/runner/` (pure), `apps/worker/src/runner/` (git, processes, files, `repos`), `apps/web/src/runs/` (routes and tools).

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are the T6.2 exports in `apps/worker/src/runner/index.ts` (`runnerHandlers` and the `RunnerExecDeps` seam in `types.ts`, `runGroup`, `scrubbedEnv`, `runGit`, `withRepo`), the T6.1 core in `packages/core/src/runner/index.ts` (`transitionStep`, `failStep`, `retryStep`, `cancelRun`, `runnerJobId`, `RunnerPort`) and `AgentNode` in `exec.ts`, the web patterns in `apps/web/src/runs/index.ts` (`withIdempotency`, `stepJson`, `keyOf`) and `apps/web/src/library/` (`Route`, `McpTool`, `servedVersion`, `manifestAndBody`, `resolveCapability`), `repos.runner.*`, `repos.library.*`, `repos.system.*` in `packages/shared/src/repositories/`, the `wf_runs`/`wf_steps` columns in `packages/shared/migrations/0005_runner.sql`, `runner.*` defaults in `packages/shared/src/env/schema.ts`, `cleanup.worktree` / `cleanup.receipts` payloads in `packages/shared/src/queues/payloads.ts`, and `runAttempt` in `apps/worker/src/jobs/consumers.ts`. The real upstream producers are the T6.2 handler and `git`: run a throwaway repo with three branches through `git merge --no-ff` once by hand (clean and conflicting) and keep the exact conflict output as a fixture `apps/worker/src/runner/fixtures/git-merge-conflict.txt`; keep a sample workflow YAML per node type as fixtures under `packages/core/src/runner/fixtures/`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to the limits object (restore it after), equal is valid, one more is an error (or is cut, where D2 says so), pin the default. Compare errors with `toEqual`/`toBe` on `message` and `code`. Must-NOT tests for every non-goal and every D6 item (no unquoted substitution in a shell line, no push without approval, no forced git, no `bypassPermissions`, no status write outside the core, no kill of a quiet shell, no duplicate step rows when `advanceRun` runs twice at once). Public names, throwaway repos and scratch schema names only. Write the gate tests with the exact names from SPEC.md. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`repos.*`, the T6.1/T6.2 core, `withIdempotency`, `JobDropped`, `runGroup`, `runGit`, `node:zlib`, `yaml`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
