# Process for T5.2: `/v1/hook/pre` (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through `deps` (`repos`, `graph`, `cache`, `caps`, `ctxOf`, `log`, `now`) and change a field of `preLimits` / `noteLimits` in a test and restore it in `finally`. Modules: `packages/core/src/graph/note/`, `packages/shared/src/schemas/pre/`, `apps/web/src/pre/`, plus the one wiring test DECISIONS.md D22 names.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are the T2.4 graph store and query functions (`apps/web/src/graph/store.ts`, `tools.ts`: `get`, and `onToolCall` which carries no session id; `packages/core/src/graph/query/{search,model,build}.ts`: what `lexicalSeeds` returns, `clean`, `weightOf`, the `GraphIndex` shape with no by-file lookup), the T5.1 code (`apps/web/src/suggest/index.ts`: the hook route pattern and race; `packages/core/src/graph/push/index.ts`: `slotOf`, `pointerOf`, the local-id rule), the T4.3 hook (`apps/web/src/memory/{hook,common}.ts`: `projectOf`, `rootOf`, `isAbs`), `apps/web/src/library/http.ts` (`Route`, `parse`), `packages/shared/src/env/schema.ts` (`graph.hint`, `graph_push.note_max`), the cache limits (`packages/shared/src/cache/limits.ts`: the 20 ms Redis budget and the 10 s breaker that the hot path lives with), and `sanitize`. The real upstream producers: (a) a PreToolUse body: `apps/web/src/spool/fixtures/*.json` show the shape Claude Code sends for PostToolUse (`session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`, `tool_name`, `tool_input`, `tool_use_id`); write PreToolUse bodies for `Read`, `Edit`, `Grep`, `Glob` and `Bash` the same way (no `tool_response`) as `apps/web/src/pre/fixtures/hook-pre-*.json`; (b) the real graph: build the graph of THIS repository once with the real pipeline (`rebuildProject`, `contextPass`, as `apps/web/src/graph/graph.query.int.test.ts` does, in a scratch schema), and keep the notes `fileNote` returns for three real files and the hints `hintLine` returns for two real greps as `apps/web/src/pre/fixtures/real-notes.json`. Read DECISIONS.md D13 against what that graph really holds (do the `implements`/`decides`/`calls` edges point where D13 expects?) and report any difference in your final reply instead of changing the decision.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: equal is valid, one more is cut or an error (as DECISIONS.md says), pin the defaults (`preLimits`, `noteLimits`, `max_chars` 400 and 401, `itemChars` 80 and 81, `note_max` 3 and 4 items, `max_nodes` 5 and 6, `per_session` 5 and 6, `quiet_s` exactly and one ms short). Compare results with `toEqual`. Must-NOT tests for every non-goal and every D6 line (no call but `byRoot`, `proj:` and `graph.get`; no model call; no write besides the `proj:` entry; a note never counted or silenced; a timed-out hint never charged; the finished text never passed through `sanitize`; never more than one line; never throws with the store, the project lookup, the cache, `ctxOf` or `log` failing; the hook never waits past the budget; frozen inputs). Public names, fakes and scratch schema names only. Write the gate file and the wiring test too (they fail until step 4). Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`slotOf`, `lexicalSeeds`, `clean`, `keyOf`, `weightOf`, `byCode`, `projectOf`, `rootOf`, `isAbs`, `errClass`, `Route`, `parse`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. The gate needs the real TEI, the scratch Postgres and Redis and about a minute (hanging endpoints wait out their budgets). If `failopen` fails on timing only, run it again once before concluding (a busy host), and report the numbers from `.ctc-dev/eval/failopen.json`; do not change a decision to chase it. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
