# Process for T5.1: `/v1/hook/prompt` and `/v1/suggest` (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through `deps` (`repos`, `tei`, `graph`, `skills`, `cache`, `ctxOf`, `log`) and change a field of `suggestLimits` / `queryLimits` in a test and restore it in `finally`. Modules: `packages/core/src/graph/push/`, `packages/shared/src/schemas/suggest/`, `apps/web/src/suggest/`, plus the two small edits DECISIONS.md D23 names.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are the T2.4 graph store and query functions (`apps/web/src/graph/store.ts`, `packages/core/src/graph/query/{search,model,build}.ts`: what `lexicalSeeds`, `denseSeeds`, `walkFrom` return and how they cut input), the T3.3 channel (`apps/web/src/skills/index.ts`: `search` result, `Degraded`, how it embeds), the T4.3 hook (`apps/web/src/memory/hook.ts`, `common.ts`: the route pattern, `projectOf`), `apps/web/src/library/http.ts` (`Route`, `ApiError`), the cache (`packages/shared/src/cache/{keys,limits,index}.ts`: `keys.sug`, `ttl.sug`, `cache.epoch`), the TEI client, `sanitize`, and `packages/shared/src/env/schema.ts` (`graph`, `graph_push`, `embed`). The real upstream producers: (a) a UserPromptSubmit body: `apps/web/src/spool/fixtures/*.json` show the shape Claude Code sends for the other hooks (`session_id`, `transcript_path`, `cwd`, `hook_event_name`); write the prompt-hook body the same way (adds `prompt`) as `apps/web/src/suggest/fixtures/hook-prompt.json`; (b) the real graph: build the D22 snapshot graph once (`testing.ts` helper) against the scratch Postgres and TEI, and keep 10 rows of what `lexicalSeeds`, `denseSeeds` and `walkFrom` return for two real ticket titles as `apps/web/src/suggest/fixtures/real-seeds.json`. Run `git log --all --no-merges --format=%s | grep 'n8n parity'` and read three issue files in the snapshot to see the gate data.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: equal is valid, one more is cut or an error (as DECISIONS.md says), pin the default (`suggestLimits`, `max_chars` 400 and 401, the floor 0.30 equal, `max_pointers` 3 and 4 candidates). Compare results with `toEqual`. Must-NOT tests for every non-goal (no repository call besides `projects.byRoot`, no `rerank`, no model call on a `sug:` hit or a blank prompt, no write besides the one `cache.set`, a degraded answer never cached, the finished line never passed through `sanitize`, never more than one line, never throws with TEI, store, channel, cache or projects failing, the hook never waits past the budget). Public names, fakes, temp dirs and scratch schema names only. Write the two gate test files too (they fail or skip until step 4). Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`lexicalSeeds`, `denseSeeds`, `walkFrom`, `nodeRef`, `queryText`, `keys`, `ttl`, `projectOf`, `rootOf`, `isAbs`, `sanitize`, `ApiError`, `errorBody`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. The gates need the real TEI and several minutes on the first run (the graph and the 6,006 skills are embedded once, then served from `.ctc-dev/eval/vec-cache/`). If `suggest.context` is below the bar, report the per-ticket table from `.ctc-dev/eval/suggest.context.json` and do not change a decision to chase it: write the finding in your report. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
