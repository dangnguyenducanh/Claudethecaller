D1  Trust. Untrusted: (a) every byte of the hook body (any local process can POST to the socket; `cwd` may be relative, huge, or point anywhere); (b) every MCP argument and every `/api` param, query and body; (c) every byte of every Claude memory file and transcript and every path under `claude_home` (a symlink can point outside; a file can be huge or not UTF-8; frontmatter can be any YAML); (d) every string read back from the database (memory text was written by a model or a user; summaries too) before it goes into the context block or an MCP reply; (e) the embedder (down, slow, wrong length). D3  Output formats (exact).
    `/v1/hook/start`: a non-empty block → `reply.code(200).send(block)` (a string; the bootstrap serves it as `text/plain`); nothing to say, or any failure, or over budget → `reply.code(204).send()`. FROM-SPEC (spec:107, spec:147 `204` empty hook reply).
    Block = `renderStartBlock` output (D11): lines joined with `'\n'`, no trailing newline, every line starts with `ctc: ` (so T4.2 `sanitize` removes the whole block if Claude Code ever stores it inside a user turn), in this order:
        ctc: # Memory · <project>
        ctc: ## Last session · <YYYY-MM-DD>
        ctc: request: <text>            (then investigated, learned, completed, `next steps`, notes; a field that is empty after cleanLine has no line)
        ctc: ## Earlier sessions
        ctc: ### <YYYY-MM-DD>            (one per older summary, newest first, followed by its field lines)
        ctc: ## Memories
        ctc: - [<kind>] <text>           (best score first)
      `<project>` = the last path segment of the project root (`/` for the root itself); dates = the UTC date of `createdAt`; every `<text>` = `cleanLine(value)` = T4.2 `sanitize`, then every whitespace run (`/\s+/g`) replaced by one space, then trim. A summary with no field line left is not shown; a section with no entry has no heading; no summary and no memory → `''` (the header is never sent alone).
    MCP replies (`McpResult`, text content):
      `mem_search`: one line per hit, best first, `indexRow(m)` = `<id> · <YYYY-MM-DD> · <kind> · <first indexChars code units of cleanLine(text)>` (cut never splits a surrogate pair), lines joined with `'\n'`; no hit → `no memories`.
      `mem_timeline`: memories and summaries merged by `createdAt` ascending (a memory before a summary at the same instant), one line each: a memory as `indexRow(m)`, the anchor's line followed by ` · anchor`; a summary as `<sessionId> · <YYYY-MM-DD> · summary · <first indexChars code units of cleanLine(request || completed || nextSteps)>`.
      `mem_get`: `JSON.stringify(rows)`, `rows` = `MemoryView[]` in the order of the requested ids (a repeated id once), ids that are unknown, another user's, or soft-deleted are left out.
      `save_memory`: `JSON.stringify({ id, action })`, `action` one of `NOOP | UPDATE | SUPERSEDE | ADD`.
      Errors: `{ content: [{type: 'text', text: JSON.stringify(errorBody(e))}], isError: true }` exactly as the library tools (apps/web/src/library/tools.ts); a `ModelError` from the embedder in `save_memory` gives code `model_unavailable` (spec:160) with message `embedder unavailable`.
    `MemoryView` = `{ id, scope, projectId, kind, text, source, confidence, pinned, reinforcementDates, supersededBy, createdAt, updatedAt, lastUsedAt, useCount }` (dates as ISO strings, `reinforcementDates` as `YYYY-MM-DD` strings, no `userId`, no embedding).
    `/api` replies: `GET /api/memories` → `200 {items: MemoryView[], next: string | null}`; `GET|PATCH /api/memories/:id` → `200 MemoryView`; `DELETE /api/memories/:id` → `204`; `POST /api/memories/import` and `POST /api/history/import` → `202 {job_id}`; `GET /api/sessions/:sid/summary` → `200 {sessionId, projectId, request, investigated, learned, completed, nextSteps, notes, createdAt}`; `GET /api/history` → `200 {items: [{path, size, mtime, status}]}`. Errors → `statusOf(e)` + `errorBody(e)` from apps/web/src/library/http.ts (spec:149-163 codes).
    Job results (what the handler resolves; stored in `jobs.result`): `memory.import` → `{files, noop, update, supersede, add, skipped}` where every considered `.md` file adds 1 to `files` and to exactly one of the other five; `memory.distill` → `{found, queued, skipped, known, young, left}` where every transcript found adds 1 to `found` and to exactly one of the other five.
    FROM-SPEC (spec:107, spec:534-537, spec:541) and FROM-CALLERS (apps/web/src/library/http.ts:24-35, :55-61, tools.ts); the block layout, the `ctc: ` prefix on every line, `cleanLine`, the timeline line format, `MemoryView`, the result shapes and `model_unavailable` in an MCP reply: YOUR-CHOICE

D4  Bad input.

D10 Recall ranking (pure).
    `rrf(legs, k)`: for each leg, each id's 1-based rank `r` (the first occurrence; a repeated id in one leg counts once) adds `1 / (k + r)`. Sorted by score descending; ties → the smaller best rank, then the earlier leg it first appeared in, then id ascending (string compare). Empty legs → `[]`.
    `recallScore(s, m, o)` = `s × 0.5^(ageDays / o.halfLifeDays) × (1 + ln(1 + d)) × (m.pinned ? 2 : 1)` where `ageDays = max(0, (o.now − Date.parse(updatedAt)) / 86400000)` and `d` = the number of distinct `YYYY-MM-DD` values in `reinforcementDates`. A non-finite result (bad date, `halfLifeDays ≤ 0`) is `0`.
    `rankRecall(legs, o)`: `rrf([legs.fts, legs.vec], o.k)`, each id scored with `recallScore` of its row (the row object from the first leg that has it), sorted by score descending, ties in `rrf` order; returns the row objects with `score` added (copies; the inputs are not edited).
    FROM-SPEC (spec:489 "RRF(full-text, vector) × 0.5^(age / 30 d) × (1 + ln(1 + distinct reinforcement days)) × (2 if pinned)", spec:527 K = 60, spec:747) ; age from `updatedAt` (it moves on every reinforcement, rewrite or patch), the tie rules and the `0` rule: YOUR-CHOICE

D11 Start block: render, measure, drop.
    `renderStartBlock(input)` renders D3 from `input.summaries` (newest first: the first is "Last session", the rest "Earlier sessions") and `input.memories` (already in score order).
    `fitStartBlock(input, maxChars)`: render; while `text.length > maxChars`, apply the next step and render again, in this fixed order, recording each applied step in `steps`:
      1. `'notes'`: remove the `notes` field from every summary;
      2. `'investigated'`: remove the `investigated` field from every summary;
      3. `'older'`: remove every summary but the first;
      4. `'halve:<n>'`: keep the first `n = floor(m / 2)` memories (`m` = the current count); repeat this step (one `steps` entry each) while still over and `m > 0`;
      5. `'last'`: remove the last summary.
    A step is applied only while the text is over; steps that change nothing are still recorded when reached (e.g. `'older'` with one summary). After step 5 the text is `''` or fits (only the header could remain, and a header alone is `''`). Returns `{ text, steps }`. `maxChars` < 1 → `{ text: '', steps: [] }`.
    FROM-SPEC (spec:528 "drop in fixed order until ≤ 10,000 chars: notes → investigated → older summaries → halve the memories → last summary", spec:572); "halve" repeated until it fits, applied to all summaries per field step, `floor`, and the measure (`text.length`): YOUR-CHOICE (two readers differ: "halve the memories" once, or repeatedly; see OPEN C1)

D12 `POST /v1/hook/start` flow (`hookStartRoute(deps)` → `{ method: 'POST', url: '/v1/hook/start', handler }`):
    0. The whole flow races a `hookStartBudgetMs` timer started on entry. The timer wins → `204` at once; the work keeps running in the background and still writes its cache entry when it finishes (spec:562 "the cached block is used on the next start"); its errors are logged by class name and swallowed.
    1. `HookStartBody` = a loose object with `cwd: string (1..cwdMax)`; then `cwd` must be absolute (`path.posix.isAbsolute`). Fail → `204`.
    2. `ctx = deps.ctxOf?.(req) ?? { userId: 'local' }`; `root = cwd` without trailing slashes (`'/'` stays `'/'`).
    3. Project: `deps.cache?.get(keys.proj(userId, root))` (value `{ id, root }`), else `repos.projects.byRoot(ctx, root)`; a found project is cached with `ttl.proj`; a miss is not cached. A cache error counts as a miss.
    4. No project → global-only mode: no summaries, no cache, and the recall rows are filtered to `scope === 'global'` (the repository's no-project read returns every project's rows: packages/shared/src/repositories/memory.ts:39-40). The project label is the last segment of `root`.
    5. With a project: `epoch = cache?.epoch.get('mem', userId, projectId)`; when it is a string, `cache.get(keys.ctx(userId, projectId, epoch))`: a string hit is the reply (`''` → `204`), no store read.
    6. `summaries = repos.memory.lastSummaries({ ...ctx, projectId }, config.memory.start.summaries)`.
    7. `query = (label + ' ' + (summaries[0]?.nextSteps ?? '')).trim()`; `vector = (await embed([query]))[0]`, or `null` when `embed` throws or returns a vector that is not 1024 finite numbers (full-text leg only, spec:206).
    8. `legs = repos.memory.recallLegs(ctxP, { queryText: query, queryVector: vector, perLeg: config.memory.rrf.per_leg })` (`ctxP` = ctx with `projectId` when known); `rows = rankRecall(legs, { k: rrf.k, halfLifeDays: half_life_days, now: now() })`, filtered as step 4, first `start.memories`.
    9. `text = fitStartBlock({ project: label, summaries, memories: rows }, config.memory.context_chars).text`.
    10. With a project and a string epoch: `cache.set(keys.ctx(userId, projectId, epoch), text, ttl.ctx)` (also for `''`); a cache error is ignored.
