# Process for T7.1: switch over (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through the `deps` arguments of the composition functions and assign to exported limits objects, restoring them in `afterEach`. Modules: `apps/web/src/server/`, `apps/worker/src/boot/`, `.claude/metric/eval/switch/`.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are the factories the mains compose: `libraryRoutes`, `graphRoutes`, `memoryRoutes`, `hookStartRoute`, `runsRoutes`, `workflowRoutes`, `suggestRoutes`, `preRoutes`, `nudgeRoute`, `createSpoolDrain`, `createSkillChannel`, `createGraphStore`, `createSessionCaps`, `graphTools`, `libraryTools`, `memoryTools`, `workflowTools` under `apps/web/src/*/index.ts`; `startWorkers`, `graphHandlers`, `libraryHandlers`, `memoryHandlers`, `memoryJobHandlers`, `extractHandler`, `withContextPass`, `withCapabilityLinks`, `workflowHandlers`, `sweepRunner`, `startRunnerLoop`, `cleanupHandlers`, `scheduleCleanup`, `blobCleanupHandlers`, `startBlobCleanup`, `watchLibrary`, `watchMemoryFiles` under `apps/worker/src/*/index.ts`; `loadConfigOrExit`, `createDb`, `createRepositories`, `createCache`, `createQueues`, `submitJob`, `createEmbedder`/`createTei`, `assertSchemaVersion`/`migrate` in `packages/shared/src/`; the testing helpers `apps/web/src/*/testing.ts` and `apps/worker/src/runner/testing.ts` show how each factory is built from real dependencies; `deploy/systemd/*.service`; `hooks/spool`; the existing `.claude/settings.json`. The real upstream producers: Claude Code's hook JSON (use the samples in `apps/web/src/spool/fixtures/` and `apps/web/src/pre/fixtures/`) and a real `curl` run: pipe each fixture through the hook commands against a throwaway Node HTTP server and keep the outputs as fixtures under `apps/web/src/server/fixtures/`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit (body 1,048,576, watchdog 2 s, bind retry 60 s, shutdown 15 s, socket path 100 bytes): shrink by assigning to the exported limits object (restore it after), equal is valid, one more is an error (or is cut where D-text says so), pin the default. Compare errors with `toEqual`/`toBe` on `code` and `message`. Must-NOT tests for every non-goal and every D21 item (no write outside `CTC_HOME`, no connect to 18310, none of the banned words in a new file, no `pg`/`kysely` import). Write the gate tests with the exact names from SPEC.md. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers. Add nothing the decisions do not list. Silence rule D24. Order: migration 0006 and its pins → `settings.json` → web composition and `main.ts` → worker `main.ts` → `run.mjs`, `switch.md`, `ci.md`. After each part run its tests, the checks (`node --import tsx agent/t7-1-switch/checks.mjs`), lint and scope. Done when tests, checks, lint and scope pass.
5. Run the gates for real: `node .claude/metric/eval/switch/run.mjs` (it can take over an hour; every gate under `timeout`). Fix the cause of every red row in your code, never by editing an earlier task's test or by skipping one. Then run the self-check and fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts, every gate that is not `pass`.
