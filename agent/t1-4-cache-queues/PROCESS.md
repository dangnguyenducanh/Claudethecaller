# Process for T1.4 cache, epochs, `ctc:inval`, queues, `dlq-retry`, systemd units (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → assign to the exported `cacheLimits`, `queueLimits` or `QUEUES` objects and restore them in `afterEach`. Modules: `packages/shared/src/cache/`, `packages/shared/src/queues/`, `apps/worker/src/jobs/`, `deploy/systemd/`.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: no call site exists yet, because these modules are built before their callers; the "call sites" are the spec sections named in DECISIONS.md D0. The real upstream producer is the scratch Redis: start from a real `redis:8.2` answer by running `INFO server` and one BullMQ `Queue.add` against it and keep the output as `packages/shared/src/queues/fixtures/redis-info.txt`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to the limits object (restore it after), equal is valid, one more is an error or an eviction, pin the default. Compare errors with `toEqual`/`toBe` on `code` and `message`. Must-NOT tests for every non-goal. Public names and unique key namespaces only. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers. Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
