# Process for T6.1: step transition table, attempts, stages, idempotency keys (TypeScript)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22, `pytest` → Vitest, `tests/test_*.py` → `*.test.ts` next to the code, `NotImplementedError` → `throw new Error('not implemented')`, docstring → TSDoc comment, `monkeypatch` → pass fakes through the `port` argument (core) or `deps` (`repos`, `enqueueStep`, `ctxOf`, `config`, `now`) and assign to the exported `runnerLimits` / `runsLimits` objects, restoring them in `afterEach`. Modules: `packages/core/src/runner/`, `apps/web/src/runs/`, `packages/shared/src/schemas/runs/`, plus the small additions to `packages/shared/src/repositories/{idempotency,tenancy.cases}.ts` and `apps/web/src/library/http.ts` that DECISIONS.md D20 names.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the call sites are `repos.runner.*` (`getRun`, `setRunStatus`, `getStep`, `listSteps`, `insertStep`, `transition`, `setStepFields`) and `repos.idempotency.*` in `packages/shared/src/repositories/`, with their `ConflictError`/`RepoError`; the `wf_steps` columns and checks in `packages/shared/migrations/0005_runner.sql`; `bullJobId` and the `runner.step` payload in `packages/shared/src/queues/`; `runner.max_failures` in `packages/shared/src/env/schema.ts`; the `Route` type and the error model in `apps/web/src/library/http.ts` and how `apps/web/src/library/routes.ts` uses them. The real upstream producer is `repos.runner`: in a throwaway script against a scratch schema, create a run, insert a step, move it `queued → running` with `repos.runner.transition`, and keep the `getStep` row (dates as ISO strings) as `apps/web/src/runs/fixtures/step-row.json`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to `runsLimits`/`runnerLimits` (restore it after), equal is valid, one more is an error (or is cut, where D2 says so), pin the default. Compare error bodies with `toEqual`. Must-NOT tests for every non-goal (no route outside the D9 list, no status write outside `transitionStep`, no enqueue for an attempt not created, no stored 5xx receipt, no token in any reply). Public names and scratch schema names only. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`repos.*`, `ApiError`, `toApiError`, `errorBody`, `statusOf`, `node:crypto`). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
