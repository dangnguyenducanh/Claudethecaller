# Process for T4.1 `hooks/spool` + `apps/web/src/spool` + `packages/shared/src/spool` (TypeScript and POSIX sh)

Every step ends with a check; the next step does not start before it passes. Language and file names adapted from the standard process: Python → TypeScript strict on Node 22 (and POSIX sh for `hooks/spool`), `pytest` → Vitest, `tests/test_*.py` → `apps/web/src/spool/*.test.ts` and `packages/shared/src/spool/*.test.ts`, `NotImplementedError` → `throw new Error('not implemented')` (sh: a script that only does `exit 0`), docstring → TSDoc comment (sh: a header comment), `monkeypatch` → assign to the exported `spoolLimits` object and restore it in `afterEach`. Module paths: `hooks/spool`, `apps/web/src/spool/`, `packages/shared/src/spool/`.

1. Read the callers and rules. Grep every call site. Done when you can say, per call site, what goes in, what is done with the result, and what the module must never do. Also run the real upstream producer on a sample and keep the output as a fixture.
   (Here: the drain's callers do not exist yet; the "call sites" are the APIs it must fit, named in DECISIONS.md D9: `submitJob` and `createQueues` in `packages/shared/src/queues/`, `projects.upsert`, `sessions.upsert`, `jobs.create` in `packages/shared/src/repositories/`, `payloads` for `graph.rebuild`/`llm.extract`/`llm.summarize`, and `spool` in `packages/shared/src/env/schema.ts`. The real upstream producer is Claude Code's hook stdin: you cannot run Claude Code, so write the four fixture payloads of D15 by hand as `apps/web/src/spool/fixtures/{post-edit,post-read,stop,session-end}.json`, then run your `hooks/spool` on each and keep one produced spool file per event under `apps/web/src/spool/fixtures/spooled/`.)
2. Write header, constants, signatures only (bodies `throw new Error('not implemented')`; the script only `exit 0`). Header: what the module is, called from, why it exists, deliberately NOT done. Each constant gets the real reason, or `chosen by judgment`: never an invented reason. Each function gets a TSDoc comment: trust, return, copies or modifies, bad input. Done when it imports and the header answers who calls it, why, and what it does not do.
3. Write tests first, covering every decision id. One behaviour per test. For every limit: shrink by assigning to `spoolLimits` (restore it after), equal is valid, one more is an error, pin the default. Compare reports with `toEqual`. Must-NOT tests for every non-goal. Public names, `mkdtemp` dirs and scratch schema / namespace names only. The gate test `memory.spool` (D15) is one of them. Done when the tests collect and fail.
4. Smallest code that passes. Reuse the repo's helpers (`submitJob`, `createQueues`, the repositories, `@ctc/shared/env` for nothing but types). Add nothing the decisions do not list. Silence rule D8. Done when tests, checks, lint and scope pass.
5. Run the self-check, fix every FAIL. Done at `SELFCHECK: DONE`.
6. Report in at most 150 words: commands and results, every `judgment:` call, doubts.
