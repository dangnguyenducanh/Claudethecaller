D0  Purpose and callers. D1  Trust. `path` comes from the T2.2 walk (relative to the project root) and is trusted to be a path, but is still validated (D4) because ids are built from it. `content` is untrusted: any file in any repo the user opens, including generated, minified, malformed or hostile text. Rules: (a) content never reaches anything but the parser and the line scanners; nothing is evaluated, imported, resolved on disk or fetched; (b) every label passes `cleanLabel` (D17): control characters (C0, C1, U+2028/2029) become a space, then the label is cut to `limits.maxLabelChars` code points, so a label cannot carry an injected line into a later prompt or block; (c) regexes run per line and are linear (no nested quantifiers over the same characters), so a crafted line cannot stall the scan; (d) tree walks are iterative or depth-capped (D6).     `ExtractedNode = { id: string; kind: 'code' | 'doc'; type: NodeType; label: string; sourceLocation: string; meta: { lines: [number, number] } }`

D4  Bad input. `extractFile` reports, never throws, for: `path` not a non-empty string, absolute (`/x`, `C:\x`, `\\x`), containing a NUL, a backslash, an empty segment (`a//b`), a `.` or `..` segment, or ending in `/` → `bad_path`; an extension `langOf` does not know → `unsupported`; `content` not a string → `internal` with message `content must be a string`; content over the byte limit → `too_large`; a language whose grammar is absent from `grammars` (also any `grammars` value that is not what `loadGrammars` returned, e.g. `{}`) → `grammar_missing` (sql and markdown need none, so they work with `{}`); anything the parser or a walker throws → `internal` with the error's class name only (message `internal: <ClassName>`). First error wins; checks run in that order.
    `loadGrammars()` is the only function that rejects: it rejects with `GrammarError` (`code: 'grammar_missing'`, message names the package, e.g. `tree-sitter-python: tree-sitter-python.wasm not found`) when a pinned WASM file is missing or fails to load. The id functions (D9) never throw on a string; non-strings are a type error at compile time and are not handled at runtime.

D9  Ids. `normalizeId(s)`: repeat { s = NFKC(casefold(s)) } until unchanged, at most 6 rounds; then every run of characters that are not Unicode letters (`\p{L}`), numbers (`\p{N}`) or `_` becomes one `_`; runs of `_` collapse to one; leading and trailing `_` are removed. `casefold` = Unicode full case folding (Python's `str.casefold`): JS has none, so build it per code point (`toUpperCase().toLowerCase()` of a single code point is close; it is wrong for Cherokee, where folding maps lower case to UPPER case, U+13F8-13FD and U+AB70-ABBF; U+13A0-13F5 stay). The 25 vectors in golden `ids.json` → `make_id` must all match exactly.
    `makeId(...parts)`: drop parts that are `''`; strip leading/trailing `_` and `.` from each remaining part; join with `_`; `normalizeId` the result.
    `fileStem(relPath)`: the path with its LAST extension removed (`a/b.test.ts` → `a/b.test`, `README.md` → `README`, `x.d.ts` → `x.d`, `Makefile` → `Makefile`, `.claude/x.md` → `.claude/x`).
    Node ids (the `kind:` prefix is the only part that is not graphify's):
      code file node `code:` + makeId(fileStem(path)); code symbol `code:` + makeId(fileStem(path), …enclosing symbol names outer to inner, name) (D11-D15 say which names count as enclosing);
      bash script entry `code:` + makeId(path WITH extension) + `__entry` (note the double `_`, it is graphify's and is not normalised away);
      markdown page `doc:` + makeId(fileStem(path)); heading `doc:` + makeId(fileStem(path), heading title) (D16).
    The suffix after `code:`/`doc:` equals graphify 0.9.93's id for every golden node. FROM-SPEC (spec:241-242 "`code:` + graphify `make_id(path_sans_ext, entity)` (casefold, NFKC, non-word runs → `_`)", spec:363) YOUR-CHOICE (the per-code-point casefold note)

D11 What becomes a node: ts, tsx, js (one rule set; js has no type syntax). Every name below goes through makeId with the file stem (and enclosing names where stated). Labels in quotes are exact.
    file: type `file`, label = base name (`index.ts`), lines [1, last line].
    class / abstract class (and `class` expressions bound by a module-level const are NOT classes, judgment if met): type `class`, label `Name`. interface: type `interface`, label `Name`. type alias: type `type`, label `Name`. enum: type `type`, label `Name`; each enum member: type `variable`, label `Member`, id makeId(stem, Enum, Member), parent the enum.
    Function declarations and generator declarations (also `export default function name`): type `function`, label `name()`. Overload signatures (`function f(a: string): void;`) are not nodes; the implementation is. A function declaration nested inside a function or method body: id makeId(stem, outer function id parts…, name), label `name()`, parent the outer node. A function declaration in the body of an anonymous function that has no named node around it (a module-level callback such as `describe('x', () => { function cb() {} })`, an IIFE): id makeId(stem, name), type `function`, label `name()`, parent the file (deeper anonymous nesting: D8).
    Methods of a class or interface: method definitions (incl. `constructor`, `get`/`set` accessors, `static`), interface method signatures, abstract method signatures, and class fields whose value is an arrow or function expression: type `method`, id makeId(stem, Class, name), label `.name()`, parent the class. Private `#x` fields and plain properties are not nodes.
    Module-level `const`/`let` declarators (directly under the program, or under `export`): value an arrow function or function expression → type `function`, label `name()`; value an object, array, `as`/`satisfies` expression, call, tagged template, or `new` expression → type `variable`, label `name`; an EXPORTED declarator with any other initializer → type `variable`, label `name`; any other non-exported declarator (number, string, binary expression, identifier, `??` …) → no node. `var` declarations → no node. Declarators inside functions, callbacks (`describe(() => { const x = … })`) or blocks → no node. Destructuring patterns: an exported object pattern yields one `variable` node per shorthand or key name; anything else → no node.
    Default export of an anonymous function or class, CommonJS `exports.x =`/`module.exports.x =`, prototype assignments: follow the golden where it has them, otherwise no node (D8).

D15 What becomes a node: sql. D16 What becomes a node: markdown (a line scanner; no markdown library, because CommonMark would add setext and indented headings that graphify does not have, and the ids would differ).
    Lines are split on `\n` (a trailing `\r` is dropped). Frontmatter: if line 1 trimmed is `---`, the first later line (within `limits.frontmatterMaxLines`) whose trimmed text is `---` or `...` closes it; lines up to the close are frontmatter (no headings, no mentions, no links); no close in range → no frontmatter. Fences: a line whose trimmed text starts with three backticks toggles "in code"; that line and every line while in code are skipped (no headings, mentions or links). `~~~` and indented code are not fences (an indented `    # x` is still not a heading because of the next rule).
    Heading: a line matching `^(#{1,6})\s+(.+)` (no leading spaces; `#tag` and `####### x` are not headings). Title = group 2 trimmed (trailing `#`s stay in the label; makeId removes them from the id). id = makeId(stem, title); if that id was already used in this file, id = makeId(stem, title, String(line)). Type `heading`, kind `doc`, label = title, parent = the nearest earlier heading with a smaller level (pop every open heading whose level ≥ this one), else the page. Lines: from the heading line to the line before the next heading with level ≤ its level (or the last line).
    Page: type `page`, kind `doc`, label = base name (`README.md`), lines [1, last line].
    FROM-SPEC (spec:242, spec:283 "Markdown yields page + heading nodes and `mentions`") YOUR-CHOICE (no markdown parser despite spec:68 "a markdown parser"; see OPEN.md)

D17 Node fields, edges, order and duplicates (all languages).
    `kind` = `code` for ts/tsx/js/python/bash/sql/json, `doc` for markdown. `type` ∈ `file class interface type function method variable key table page heading` (D11-D16). `label` = the rule's label passed through `cleanLabel` (D1). `sourceLocation` = `L` + start line. `meta.lines` = [start, end]: start = the declaration's first line (decorators excluded, D12), end = its last line (for a class: the closing brace line; for an arrow const: the declarator's last line), both 1-based, end ≥ start; a file/page/entry spans [1, number of lines] (empty file [1, 1]; a final newline does not add a line).
    One `contains` edge from each node's parent to it (src parent, dst child, `confidence: 'EXTRACTED'`); the file/page node has no parent. Parent = the node the D11-D16 rule names (golden `parent`); the file node for top-level symbols.
    Order: the file/page node first, then all other nodes in document order (start line, then start column; nodes that start at the same position: outer first); edges in the order of their dst node.
    Duplicate id in one file (overloads aside, D11; e.g. two `def f` in one module, a getter and a setter with one name): the FIRST occurrence is kept with its own line, later ones are dropped together with everything nested only under them (their children keep their ids if those ids are new); markdown headings use the line suffix instead (D16). YOUR-CHOICE (types `variable`, `key`, `table`; the order) FROM-SPEC (spec:252 `contains` file → symbol, class → method)

D18 Raw imports (`RawImport = { from: string; specifier: string; names: { imported: string; local: string }[]; typeOnly: boolean; kind: 'import' | 'reexport' | 'require' | 'dynamic' | 'source'; line: number }`), `from` = the file node id always; one entry per statement, in document order; T2.2 turns them into `imports`/`imports_from` edges.
    ts/tsx/js: `import d, { a as b, type c } from 'x'` → kind `import`, names [{imported:'default',local:'d'}, {imported:'a',local:'b'}, {imported:'c',local:'c'}]; `import * as ns from 'x'` → [{imported:'*',local:'ns'}]; `import 'x'` → names []; `import type …` or every specifier marked `type` → typeOnly true. `export { a as b } from 'x'` → kind `reexport`, [{imported:'a',local:'b'}]; `export * from 'x'` → [{imported:'*',local:'*'}]; `export * as ns from 'x'` → [{imported:'*',local:'ns'}]. `require('x')` with a string literal anywhere → kind `require`, names [] (judgment: bindings of `const {a} = require()` may be added as names); `import('x')` with a string literal → kind `dynamic`, names []. Non-literal specifiers → no entry.
    python: `import a.b` → specifier `a.b`, names [{imported:'*',local:'a.b'}]; `import a.b as c` → [{imported:'*',local:'c'}]; `from ..m import x as y, z` → specifier `..m` (leading dots kept; `from . import x` → `.`), [{imported:'x',local:'y'},{imported:'z',local:'z'}]; `from m import *` → [{imported:'*',local:'*'}]; all kind `import`, at any depth (inside functions too); inside an `if TYPE_CHECKING:` (or `typing.TYPE_CHECKING`) block → typeOnly true.
    bash: `source <word>` and `. <word>` where the word is a plain or quoted string without `$` → kind `source`, specifier = the word unquoted, names [].
