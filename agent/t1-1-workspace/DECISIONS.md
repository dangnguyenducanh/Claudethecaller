D0  Purpose and callers.
    Creates the TypeScript half of the repo: a pnpm workspace with five packages, strict TypeScript, Vitest, an ESLint rule that keeps SQL drivers out of everything but the repositories module, and the Zod loader for `config/*.yaml`. Done = `pnpm -r lint && pnpm -r typecheck && pnpm -r test` green on nearly empty packages (FROM-SPEC spec.md:773, 757).
    Callers: every later TS task imports `@ctc/shared` / `@ctc/core` (T1.2 to T6.3); `.github/workflows/ci.yml` and `scripts/check.sh` run the three commands; apps/web, apps/worker, apps/cli call `loadConfigOrExit()` at start (FROM-SPEC spec.md:84, 208, 217-219).
    Packages (FROM-SPEC spec.md:86-99): `apps/web`, `apps/worker`, `apps/cli`, `packages/shared`, `packages/core`. `packages/shared` holds the subfolders repositories, schemas, env, queues, migrations; `packages/core` holds graph, library, memory, runner. Only `env` gets code in this task.

D1  Trust.
    `config/*.yaml` and env vars are written by the operator, not an attacker. The failure to prevent is a typo or wrong type that silently falls back to a default (FROM-SPEC spec.md:208 "bad config key: Zod at startup; process exits with the YAML path of the bad key"; FROM-CALLERS src/ctc/config.py:49 "a typo fails at load, not at the first query").
    YAML is still parsed defensively: aliases refused (`maxAliasCount: 0`), YAML 1.2 core schema, no custom tags (YOUR-CHOICE; mirrors spec.md:404 for frontmatter). A config error message never contains the value of `database_url` or `redis_url` (they carry passwords; YOUR-CHOICE).

D4  Bad input.
    Never throws on the first problem. `loadConfig` collects every issue from every file and from env, then throws one `ConfigError` (YOUR-CHOICE; FROM-SPEC spec.md:208 names "the bad key"). Problems that count as issues: missing required file; YAML syntax error; top-level value that is not a mapping (an empty file or `null` is an empty mapping, not an issue); Zod failure; duplicate top-level key across files; bad env value; unknown key (see D5 for which keys are known).
    Unknown key rule (YOUR-CHOICE): in the sections defined by spec.md (`graph`, `library`, `spool`, `memory`, `runner`, `embed`, `ranking`, `graph_push`, `db_pool`) an unknown key is an issue (`graph.shrink_gaurd: Unrecognized key`). At the top level an unknown key is an issue unless it is listed in D5.

D5  Odd but harmless input.
    These Python-era top-level keys stay valid and are returned untouched under `config.legacy`, because today's `config/*.yaml` still contains them while Python serves (FROM-CALLERS config/retrieval.yaml:12-30, config/server.yaml:10-21): `abstain_below`, `gate_path`, `gate_min_p`, `gate`, `agent_min_rerank`, `blend`, `memory_weight`, `memory_in_query`, `topic_shift_below`, `graph_links`, `writer`, `jobs`, `history`, `graph_extract`. Inside `cache`, keys other than the typed ones (e.g. `semantic_min_cos`, `stream_maxlen`) are accepted and kept.
    A bare `gate: {kind: off}` is the string `"off"` (YAML 1.2; Python's YAML 1.1 read it as false, FROM-CALLERS src/ctc/config.py:47). An empty file, comments only, or a missing optional `ctc.yaml` is valid. A quoted number where a number is wanted (`port: "18310"`) is an issue, not coerced (YOUR-CHOICE: no coercion in YAML; only env strings are converted).
    The real `config/` directory of this repo, unchanged, must load with zero issues (integration).

D6  Must never.
    Crash with anything but `ConfigError` on junk input (binary bytes, a 5 MB file, `null`, a list, numbers as keys, aliases, tabs, a directory named `models.yaml`); modify its `env` argument, `process.env` or any file; hang (sync reads only, no network); print a secret (D1); return a different result for the same input (issue order is sorted); read `.env`, the current directory or the network.
    `eslint.config.js` must never report a false pass for the ban in D11: a banned import fails in `.ts`, `.mts`, `.js` and `.mjs` files.
