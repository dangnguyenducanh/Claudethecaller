## Architecture

boxes:
- `orca CLI` | client | `src/cli`; parses `CommandSpec`, calls runtime RPC, prints text or `--json`. Groups: project, repo, worktree, agent, file, terminal, orchestration, computer, linear, jira, emulator, browser, skills, serve.
- `Runtime RPC server` | core | `src/main/runtime/rpc`; auth, permission tiers, method dispatch, mutation receipts. Lives in Electron main (app) or in `orcad` (headless, `orca serve`, port 6768).
- `OrcaRuntimeService` | core | `src/main/runtime/orca-runtime*`; façade used by RPC methods: worktrees, terminals, agent launch, status.
- `Orchestration engine` | core | `src/main/runtime/orchestration`; Runs, Tasks, Dispatches, worker_dispatches, messages, gates, deliveries.
- `orchestration.db` | store | SQLite in userData; WAL; schema v43.
- `Worktree/git layer` | core | `src/main/git`, `src/main/ipc/worktrees`; shells out to `git` (execFile), tiered admission scheduler.
- `Hook runner` | core | [hooks ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/hooks.ts), [worktree-runner-script ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/worktree-runner-script.ts); [orca ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/orca.yaml) setup/archive scripts.
- `Agent launch executor` | core | `src/main/agent-launch`; picks terminal vs structured surface, delivers prompt, returns receipt.
- `Terminal daemon` | process | `src/main/daemon`; separate Node process owning PTYs (node-pty), survives app restart.
- `Agent process` | process | `claude` / `codex` / ... TUI in a PTY, or Claude stream-json child for chat.
- `Agent hook server` | core | `src/main/agent-hooks`; loopback HTTP on random port, token header; builds per-pane status rows.
- `Agent-session journal` | store | `agent-session-journal.db` (v4); chat transcript rows, session records, tabs.
- `Renderer / mobile / web client` | client | React UI over IPC or RPC; same RPC for remote.
- `Integrations` | edge | Linear, Jira, browser (CDP), computer-use, emulator; exposed as CLI groups + RPC methods + skills.
- `Relay` | edge | `cloud/apps/relay`; pairs phone and desktop by splicing outbound WebSockets.

arrows:
1. `orca CLI` -> `Runtime RPC server` | JSON request, token from `orca-runtime.json` (unix socket) | hot
2. `Renderer` -> `Runtime RPC server` | IPC/WS same methods | hot
3. `Runtime RPC server` -> `OrcaRuntimeService` | handler call after zod + permission check | hot
4. `OrcaRuntimeService` -> `Orchestration engine` | worker-start, send, check, worker_done | hot
5. `Orchestration engine` -> `orchestration.db` | sync node:sqlite txns (BEGIN IMMEDIATE / SAVEPOINT) | hot
6. `OrcaRuntimeService` -> `Worktree/git layer` | createManagedWorktree -> `git worktree add` | cold
7. `Worktree/git layer` -> `Hook runner` | setup script after add, archive script before remove | cold
8. `Agent launch executor` -> `Terminal daemon` | create PTY with env + startup command | cold
9. `Terminal daemon` -> `Agent process` | node-pty spawn, stdin writes (prompt paste, mail pointer) | hot
10. `Agent process` -> `Agent hook server` | hook script curl POST (state, prompt, tool, session id) | hot
11. `Agent hook server` -> `OrcaRuntimeService` | status rows; gate mail pointer delivery on `idle` | hot
12. `Agent process` -> `orca CLI` | worker runs `orca orchestration send/check/ask` itself | hot
13. `Agent launch executor` -> `Agent-session journal` | first message and chat turns for structured sessions | cold
14. `Orchestration engine` -> `Terminal daemon` | mailbox "pointer" line typed into idle agent PTY | hot
15. `Runtime RPC server` -> `Relay` | outbound WS for phones | cold
16. `Integrations` -> `Runtime RPC server` | CLI/RPC method groups | cold

## 0. Domain model, interfaces, processes, lifecycle, config, budgets, egress

- **Domain model:** Run (namespace + coordinator inbox) -> Task (work, `deps` JSON array, status pending/ready/dispatched/completed/failed/blocked) -> Dispatch (one attempt, `retry_of_dispatch_id`, status pending/dispatched/completed/failed/circuit_broken) -> `worker_dispatches` (infra of the attempt: starting, ready, start_unknown, failed, succeeded, stopping, stop_unknown, stopped, abandoned) (`types.ts:20-170`). Plus messages, deliveries, decision_gates, questions, attempt_observation_facts.
- **Worktree identity:** `repoId::absolutePath`; also folder workspaces (no git). Lineage parent/child recorded in app store.
- **Interfaces:** CLI -> RPC -> `OrcaRuntimeService`; hook scripts -> loopback HTTP; agents -> same CLI. Mail types: status, dispatch, worker_done, merge_ready, escalation, handoff, decision_gate, question, heartbeat (`types.ts:4-14`).
- **Process model:** Electron main hosts runtime; terminal daemon is a separate process (survives app quit); `orcad` is the same runtime headless on pinned Node; each agent is a PTY child or an SDK stream-json child; hooks run as short shells.
- **Supervision:** daemon owns PTY lifetime; process-group kill for hooks and Claude children (`@orca/process-host`); POSIX supervisor stops Claude if Orca dies ([claude-agent-sdk-process-spawn ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/claude/claude-agent-sdk-process-spawn.ts) comment). No supervisor restarts a dead agent; recovery is explicit (retry-of).
- **Data lifecycle:** worktrees persist until `rm`; mutation receipts pruned at 10 000 rows or 30 days; agent status rows hydrate max 7 days; worker output archived at release.
- **Config:** global settings (workspaceDir default `~/orca/workspaces`, branch prefix, heartbeat on/off + 1-60 min, nested depth, Chat UI mode); per-repo [orca ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/orca.yaml) keys `scripts`, `setupAgentStartupPolicy`, `issueCommand`, `defaultTabs`, `environmentRecipes`, `worktree` (`hooks.ts:126`); env overrides `ORCA_WORKTREE_ADD_TIMEOUT_MS`, `ORCA_USER_DATA_PATH`.
- **Resource budgets:** see Appendix tuning values. No global cap on workers; only nesting depth (default 1) and per-start timeouts. Git work is admitted through a tiered scheduler ([git-admission-scheduler ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/shared/git-admission-scheduler.ts)).
- **Egress:** agents talk to their own vendors; Orca itself: GitHub/GitLab/Linear/Jira APIs, PostHog telemetry, relay WebSocket, update feed. Hook server and RPC bind loopback only; `orca serve` opts into LAN pairing.

## 1. API / protocol and errors

- **RPC:** one method name per operation (`orchestration.workerStart`, `orchestration.gateCreate`...), `defineMethod({name, permission, params: zod, handler})`; response envelope with `_meta.runtimeId`; failure `{code, message, data}` ([core L56-77 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/runtime/rpc/core.ts#L56-L77)).
- **Versioning:** `RUNTIME_PROTOCOL_VERSION = 3`, `ORCHESTRATION_CONTRACT_VERSION`, capability negotiation per socket; unknown optional fields treated as absent; new stream ops need advertised capability.
- **Streaming/long-poll:** `check --wait` and `ask` are long-polls with 10s keepalives and abort on disconnect ([unix-socket-transport L10 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/runtime/rpc/unix-socket-transport.ts#L10)).
- **Errors:** `OrchestrationError(code, message, data)` with stable codes (`task_not_found`, `task_not_startable`, `inject_rejected`, `nested_worker_depth_exceeded`, `consumer_fenced`, `dispatch_inactive`, `terminal_handle_stale`); `error.data.nextSteps` gives exact recovery text. CLI exits 0 only for `ready`; failed or `outcome_unknown` exits 1 with `failedStage`, `residualResources`, recovery commands.
- **Idempotency in the API:** every orchestration mutation accepts `--retry-request <id>`; `request-show` answers completed / pending / absent.

## 4. Sync vs async, process spawning, retries

- **Sync DB, async everything else:** SQLite calls are synchronous in the main process; slow work (git, hooks, PTY) is awaited. `worker-start` is one blocking RPC whose client timeout = readiness timeout + 50s ([orchestration-timing-budgets L7 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/shared/orchestration-timing-budgets.ts#L7)).
- **Spawning:** git via `execFile`; hooks via `spawn(script, {shell: bash, detached})` with process-group SIGTERM then force kill after 2s (`hooks.ts:57,170-220`); agents via daemon PTY or SDK spawn hook.
- **Retries:** none automatic for workers. Retry is an explicit `worker-start --task T --retry-of D` that must restate placement. Third failure circuit-breaks the Task ([dispatch-circuit-breaker L1 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/runtime/orchestration/db/dispatch-context/dispatch-circuit-breaker.ts#L1), [dispatch-completion L167 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/runtime/orchestration/db/dispatch-context/dispatch-completion.ts#L167)). Prompt delivery retries stop once PTY write effects are ambiguous (`core.ts` `markMutationEffectPossible`).
- **Stale-base guard:** dispatch refused if worktree is more than 20 commits behind base unless the spec has `allow-stale-base: true` ([coordinator-stale-base-flag L2 ↗](https://github.com/stablyai/orca/blob/2c4eb87240a24a0dc83de82db075aa81eb3457a2/src/main/runtime/orchestration/coordinator-stale-base-flag.ts#L2)) [legacy coordinator path].
