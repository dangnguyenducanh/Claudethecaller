## Architecture

boxes:
- web | app | Next.js: UI, tRPC, public REST `/api/public/*`, MCP `/api/public/mcp`, `/api/chatCompletion`
- worker | app | Express + BullMQ: 44 queues (`QueueName`), ingestion, entity-change, webhooks, evals, in-app agent
- shared | lib | `@langfuse/shared`: Prisma, `PromptService`, `SkillCacheService`, queues, repos, zod schemas, RBAC
- native | lib | Rust napi addon used by worker/shared for codec/hash/cluster
- ai-gateway | app | Rust proxy to provider APIs, emits OTLP generations
- postgres | store | prompts, prompt_dependencies, prompt_protected_labels, skills, skill_files, skill_blobs, api keys, audit logs
- clickhouse | store | traces/observations/events; observation rows carry prompt id/name/version and `skills_available`/`skills_resource_loaded`
- redis | store | BullMQ, prompt cache + epoch token, skill reference cache, api-key cache, rate limits
- s3 | store | event payloads, media, exports
- sdk/cli/agent | client | SDK `get_prompt`, `langfuse skills install` CLI, MCP clients, Claude Code
- in-app agent | app | Mastra agent in worker; loads bundled + hosted skills
- langfuse-skills | lib | bundled "how to use Langfuse" skills (`name, description, instructions`), synced nightly from `langfuse/skills`

arrows:
1. sdk/cli/agent -> web (`GET /api/public/v2/prompts/{name}?label=`) | hot
2. web -> redis (prompt cache epoch + entry, 1h TTL) | hot
3. web -> postgres (cache miss: `prompts` + `prompt_dependencies` walk) | hot on miss
4. sdk -> web (ingestion with promptName/promptVersion) -> s3/redis -> worker | hot
5. worker -> postgres/redis (`PromptService.getPrompt` + `SkillCacheService.getReferences` enrichment) -> clickhouse | hot
6. web (create/label move) -> postgres tx -> redis (rotate epoch) | cold
7. web -> redis queue `EntityChangeQueue` -> worker -> trigger match -> `WebhookQueue` | cold
8. ui/tRPC `skills.*` + REST `/api/public/skills*` + MCP skills tools -> `SkillService` -> postgres | cold (read path uncached)
9. cli/agent -> web (`GET /skills/{name}?label|version&includeContent`, `/skills/files/content?sha256Hashes=`) | warm
10. worker in-app agent -> web (`/api/public/skills?tag=`) with project keys, 5 s timeout -> merge with bundled skills | cold
11. playground ui -> `/api/chatCompletion` -> LLM provider; Save-to-prompt -> tRPC `prompts.create` | cold
12. experiments (`promptExperiments:CUD`) -> `PromptService.resolvePrompt` -> `ExperimentCreate` queue | cold

Prompt serving highlight: arrows 1-3 (SDK read) and 5 (ingestion linking). Skill serving: 8-10.

## 3 Storage, indexes, idempotency, migrations

- Prompt indexes: `unique(projectId,name,version)`, `(projectId,id)`, `createdAt`, `updatedAt`, GIN `tags`; **no index on `labels`** so label reads rely on the `(projectId,name,...)` prefix. Skill indexes: unique `(projectId,name,version)`, GIN `tags` and `labels`, `skill_files unique(projectId,skillId,path)`, `skill_blobs unique(projectId,sha256Hash)`.
- Hash: sha256 base64 (44 chars), regex-validated canonical form (`types.ts:SkillVersionFileReferenceSchema`).
- Version allocation: prompts = read max + unique violation retry; skills = advisory lock per `(project,name)` inside the tx (no retry needed).
- Label uniqueness: app-level; prompt tRPC path unlocked (race possible) [UNVERIFIED impact].
- Migrations: Prisma `migrate` (464 dirs; skills = `20260924174440_skill_management`), ClickHouse canonical SQL migrations (`0053` adds skill columns).
- Delete semantics: `skills -> skill_files` cascade, `skill_files -> blob` Restrict.
- ClickHouse stores prompt id/name/version + skill refs per observation; ReplacingMergeTree dedupe (not re-derived).

|---|---|
