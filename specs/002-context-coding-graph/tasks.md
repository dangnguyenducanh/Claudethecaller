# Tasks: Context + coding graph (m6)

**Input**: `specs/002-context-coding-graph/` — [plan.md](plan.md), [spec.md](spec.md), [design.md](design.md), [data-model.md](data-model.md), [contracts/](contracts/), [research.md](research.md), [quickstart.md](quickstart.md)

**Tests**: requested (CLAUDE.md "one runnable check", plan.md Testing). Each ticket writes its test file first and it must fail before the implementation tasks.

**Organization**: by ticket and wave (plan.md "File Locks and Lane Plan"); each ticket maps to the user stories it delivers. Tickets are named **ticket 01–07** here (= G1–G7) to keep them apart from task ids T###.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an unfinished task)
- **[Story]**: US1–US8 from spec.md

## Rules for every builder

- Branch `m6-graph`; builders never commit, push, start/stop the daemon or containers, touch `.env`, the real `~/.claude`, or the Supabase URL (`.env` line 2). The lead commits each ticket.
- Scratch DB only: `export CTC_DATABASE_URL=<the URL on .env line 3, commented, 127.0.0.1:18304>` in your shell; tests skip when it is unset or contains `supabase`.
- Edit only the files your ticket owns (plan.md lock table). Code style: CLAUDE.md (shortest working solution, no new dependencies, `ponytail:` on known corner-cuts, match surrounding comment density).
- Use `graphify query "<question>"` before grep/read when exploring code.
